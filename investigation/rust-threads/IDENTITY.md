# Identity and ownership

The inputs are the M9b `e292cefe` water rules and already normalized model/initial/forcing bytes. `src/lib.rs` is the profiled scalar port from `2ebeea87`. `prepare-parallel.mjs` extracts its flow, depth and dam expressions verbatim, adapting only buffer access and exactly rounded `ceil`. The shared candidate retains TypeScript bookkeeping and stopping around these Rust kernels. `build.mjs` derives the threaded TypeScript control from the same bookkeeping and TypeScript expressions; runtime, helper and isolation files originate at parallel-water `68d68313`. Product files are read, never written.

For valid models with finite numeric trajectories, assume the state agrees before a substep:

1. The coordinator prepares the complete unique wet/active lists, stale-flow clearing and modifiers in the original order. Thread `id` owns `[floor(count*id/threads), floor(count*(id+1)/threads))`. These intervals partition the list for every positive count, including uneven lengths and empty intervals.
2. Flow reads old state and writes only four flow slots of its own tiles. The coordinator publishes parameters, indices and an epoch with sequentially consistent Atomics; every helper acknowledges completion before depth begins. No neighbour flow is read while it is being written.
3. Depth reads complete flows and old concentration. It writes only its tile's depth, old depth, concentration scratch and momentum. Its arithmetic does not read a neighbour's new depth. A second acknowledgment barrier precedes concentration commit and source application.
4. Sources (including overlapping cells), seep hysteresis, membership/cache changes and evaporation stay serial and ordered. There are two substeps and four phase barriers per tick. Four-direction sums retain expression order; volume and sealed-basin sums remain full row-major reductions. Stopping checks and slice boundaries are unchanged. No floating point accumulation spans workers.
5. All arithmetic is strict binary64, with JavaScript-compatible maximum/signed-zero handling and exact ceil. Neither scalar nor shared LLVM IR contains fused, relaxed, reassociated or transcendental arithmetic. Therefore each phase, source update, tick and stopping check agrees by induction, independently of partition boundaries or thread completion order. Timing never decides numerical stopping.

Migration uses typed-array copies, with no arithmetic. A single shared linear memory holds 141 bytes/tile, including the index list, plus descriptor/alignment space, a 2 MiB prefix and one private 64 KiB stack per Wasm instance. Each instance imports this memory and owns its stack; no shared allocator runs. Per-element/range Rust references cover only a tile owned by that worker. Barriers exclude conflicting accesses; descriptor/topology remain unchanged while workers execute. Private JS output arrays are restored at run boundaries and cannot be overwritten by the next map. The generated raw-pointer kernel is an internal ABI for trusted, validated topology/list ownership, not an arbitrary public pointer API.

The 1,024 list entries per configured thread cutoff changes execution placement only. Below it the coordinator executes the same Rust or TypeScript kernel without helpers. One thread means coordinator only. Above it every helper must acknowledge; a missing helper fails the task. Pool startup failure or missing isolation chooses scalar TypeScript before advancing. A phase failure can leave partial shared state: discard that simulator and retry from original model/forcing on a fresh scalar simulator. Never resume the partial state. `fault-check.ts` tests startup failure, intentional stalled depth phases, interleaved maps, mutable floor/forcing and private output identities.

Firefox measurements disable the Wasm baseline tier, enable the optimizing tier, disable lazy tiering and require the diagnostic Juggler flags from rust-analysis/PROFILE_REPORT.md. Successful scalar/shared compilation therefore cannot be a baseline-only measurement. The executable is unchanged Firefox 146; only its test debugger was corrected. The harness refuses an unexpected backend fallback.

The numerical kernel and helper binaries are unchanged by the simulation-only timer correction. The earlier 216,000 forced per-tick checks retain their own bundle fingerprint in ignored identity-evidence.json. The final matrix independently checks every complete settle against archived bytes and stopping ticks. The separate one-tick Weather check computes forcing once in Node, encodes it once, and serves the identical SHA-256-attested input to every engine/count; this covers forcing cadence without claiming portable native transcendental maths.

This proves partition independence under the stated numeric/ownership contract. Byte tests check the compiled implementations, not every future compiler or all possible input values. Planning/native transcendental weather computation is outside the boundary: supply identical model and ordered forcing bytes. No unrestricted cross-engine terrain-generation claim is made.
