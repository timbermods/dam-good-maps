# Performance architecture audit

**Recommendation: finish the exact water core, remove presentation stalls, and hydrate saved state before widening the architecture.** Performance is a release requirement. Determinism, Timberborn's floating-point water rules and “what you see is what you get” remain acceptance gates; canonical water/world state never uses fixed-point or GPU compute.

Read latest fetched `dev` **1416a9b2** and `feature/m9b` **e292cefe**. Product code is unchanged. Read all eight prior investigations first; [SOURCES.json](SOURCES.json) pins reports and local evidence. Rust-water and gen-speed had in-progress local material but no final REPORT.md at capture; their unfinished matrices are not certified gains. Existing candidates were not rerun.

Separate 1 ms V8 leaf profiles at 256² put `substep` at **29.5% dev / 59.8% M9b**. Dev also spends 20.0% in `features/geometry.ts:pathField`, 10.1% in `analysis/damsites.ts:damCandidate`, 5.7% in drainage. These one-run samples guide scope, not tail guarantees.

Prior evidence is more diagnostic than these loaded wall times:

- **Water-speed:** 77–81% flow-substep CPU; its exact scalar candidate has 1.25× screened median gain, with some repeated regressions. M9b already contains it; dev does not. Do not count it again as Rust's gain.
- **Performance/smoothness:** executing stacks identify Standard main-thread blending 74.23/72.21 ms wall/CPU, brush release/object riding 62.57/59.69 ms, High ambient update 126.65/122.28 ms. Native five-repeat worst-frame median/worst: 127.2/133.3 ms. Multi-second freeze remains unexplained; broad and scratch-only patches lack adoption proof.
- **Gen-speed:** existing seed-1 leaf samples put `substep` at 51% River Valley, 24% Canyon, 77% Islands. Its verified shared-input example reduces drought calculations **12→2**, retaining four start selections; no complete timing matrix is available here.

## Ranked roadmap: staged Rust/core

**1. Water**, with resident buffers and operation boundaries below; independent-map batch pools first, within-map threads only after qualification. **2. Forces' planning and analysis**, including the profiled geometry/dam kernels (`forces/runs.ts` planners, `forces/glaciate/plan.ts:planGlaciate`, `analysis/walk.ts:walkDistance`, `validate/playability.ts:checkPlayability`). **3. Generator after M9b's release** (`gen/generate.ts:generate`, `land/field.ts:makeField/erodeHard`, `land/hydro.ts:planHydro`, `gen/settler.ts:pickStart`). Preserve this order; renderer/storage can progress alongside it. Core paths are under `src/core/`; renderer/editor/worker/ui/platform paths under `src/`. Short filenames share the preceding directory.
