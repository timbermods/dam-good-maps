# Reproductions and fixes

Reviewed source: `feature/page` commit `32e07fe955ab0f759b5d9d61d9b0b37b83cb4344`. The PR itself is based on `dev` and contains only investigation files; it does not carry the page branch's product changes.

`saving.test.ts` executes the actual App controller source before JSX rendering. Its hooks retain refs/state and record effects; worker replies and storage writes can be held independently. It uses the actual saver and IndexedDB adapter, backed by fake-indexeddb. It does not run a complete Preact render cycle, worker generation, or browser UI. In particular, F2 preserves worker RPC ordering and delays **storage**, not a worker reply overtaken by a later open. Safe-outcome assertions fail on the original and pass with both adoption patches.

The leave warning is deliberately limited: browsers may suppress it before user interaction, on mobile/process termination, or when the player chooses to leave anyway. A pagehide/visibility flush is best effort; it cannot make asynchronous worker/IndexedDB writes survive arbitrary termination. F1's test verifies cancellation protection, not an impossible guarantee of completed writes on unload.

The conflict fix retains the first committed project and leaves the rejected draft in the editor with download guidance. It does not merge edits or automatically create a recovery copy. A newly opened saved map clears the old map's failure state. Explicit local deletion cancels queued callbacks, waits for an in-progress storage write, then removes it. That cancellation avoids the original null-entry snapshot/error; same-tab resurrection itself was **not** reproduced and is not reported as a finding.

Controls in `controls.test.ts` retain both distinct-map projects, keep an open-map rename through a running snapshot and later queued save, keep a closed-map rename during another map's pending save, and keep a same-tab deleted map absent. The quota probe injects an asynchronous QuotaExceededError in the project-put request **after entry-put succeeds**, using fake-indexeddb's real request/abort/rollback machinery. The old entry and bytes both survive. The original adapter leaves an unhandled transaction rejection; the patch consumes that rejection/aborts on callback errors, without treating it as a sixth data-loss finding. Physical disk exhaustion was not attempted.

The existing `yourMaps.test.ts` (14 tests) and `olderGenerator.test.ts` (2 tests) run from the pinned source. The latter moves the start and deletes a generated river, reopens the edited projects with an older generatorVersion, and compares terrain and objects. Those cases passed on both implementations. This rules out that reproduced version-bump scenario; it does not assert byte-exact replay under arbitrary future changes beyond D455/D382.

Results: original **9 fail / 22 pass**; patched **31 pass**. Product and patched-source TypeScript checks pass. Tests use at most four workers, with files run sequentially. No browser or large generation batches were needed. Generated archives/copies stay in ignored `local/`; `prepare.mjs` recreates them from the pinned Git commit in a few seconds, and the targeted suite takes a few seconds on this machine.
